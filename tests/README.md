# الاختبارات

يحتوي `tests/` على اختبارات Python الوحدوية والتكاملية لمشروع Manuscript Doctor. يركز الاختبار على السلوك القابل للملاحظة، لا على مجرد تنفيذ الدوال دون تحقق من الأثر.

## نطاق الاختبارات

| المجال | ما يتم التحقق منه |
| --- | --- |
| العمليات | الأبعاد، القنوات، المعاملات، والأثر المتوقع لكل عملية |
| registry | تعريف العملية وتصنيفها وحدودها |
| Smart Pipeline | الأهلية، البوابات، rollback، وعدد المحاولات |
| Preparation | قبول deskew-only عند الثقة العالية ورفض الحالات غير الآمنة |
| Preservation | عدم تعديل الأصل وقياس مخاطر الأثر |
| Flask integration | الرفع، Preview، الاعتماد، النتائج، والتنزيل |
| Super Resolution | التكبير 2×/3×، alpha، الحدود، وحماية حجم الناتج |

## تشغيل الاختبارات

من جذر المشروع:

```bash
PYTHONPATH=/home/ubuntu/image_project_split pytest -q
```

النتيجة الحالية الموثقة:

```text
333 passed, 16 skipped
```

يحدد `pytest.ini` مجلد `tests` كمصدر الاختبارات الرسمي، ويمنع جمع النسخ المكررة داخل مجلدات الإصدار أو أدوات التشغيل.

## فحص JavaScript المرتبط

```bash
node --check static/js/parts/*.js
```

ينبغي تشغيل هذا الفحص عند تعديل ملفات الواجهة المقسمة، ثم مراجعة المسار اليدوي في المتصفح عند تغيير الحالة أو المعاينة أو الاعتماد.

## قاعدة الاختبار

لا يكفي أن تعيد العملية صورة؛ يجب إثبات أن الصورة الأصلية لم تتغير، وأن الأبعاد والقنوات صحيحة، وأن السلوك يتوافق مع نوع العملية. أما صور C05 وC06 فتستخدمان كأدلة QA لمسار Smart Preparation وليستا بديلاً عن اختبار الصور المتنوعة.
