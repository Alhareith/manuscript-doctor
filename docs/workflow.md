## تدفق المستخدم

1. يختار المستخدم صورة.
2. يتحقق التطبيق من الملف ويحفظه مؤقتًا.
3. يحلل التطبيق الصورة ويعرض التقرير.
4. يختار المستخدم عملية يدوية أو Smart Pipeline.
5. يعرض التطبيق النتيجة مقابل الأصل ويتيح تنزيلها.

## التدفق الذكي

`قياس → تحديد المشكلة → اقتراح الخطوات → معالجة → عرض السبب والنتيجة`

يجب أن تكون الخطوات المقترحة قابلة للتفسير، مثل: «التباين ضعيف، لذلك اقتُرح CLAHE». الاقتراح ليس حكمًا نهائيًا على جودة المخطوطة.

## الأخطاء

قبل رفع صورة أو عند اختيار ملف غير صالح أو فشل قراءة الصورة، يوقف التطبيق العملية ويعرض رسالة عربية قصيرة.

## الخطوة التالية

تطبيق هذا التدفق في الواجهة ومسارات Flask عند مرحلة التنفيذ.

## User Workflow
1. Select manuscript image.
2. Preview the selected image.
3. Upload and analyze.
4. Review image diagnosis.
5. Review recommended action.
6. Choose automatic or manual processing.
7. Review the processed result.
8. Compare the result with the original.
9. Review the processing summary.
10. Download the selected result.
